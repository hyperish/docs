# hyperish/docs

하이퍼리쉬(Hyperish) 프레임워크 패밀리의 범용 명세 레포입니다.

이 레포의 문서는 모든 제품과 코드 레포가 공유하는 **추상 계약과 공통 규칙**입니다. 특정 제품의 사례나 설계, 특정 코드 레포의 구조·책임·구현 세부는 담지 않습니다. 그런 내용은 각 제품·각 코드 레포의 문서에 둡니다. DX(개발자 경험)와 응용/개발 계층의 기획을 다룹니다.

예외는 레포를 찾고 결정을 잇기 위한 최소 정보 세 가지뿐입니다: 레포 역할표([00](docs/00-vision.md)), 여러 레포가 함께 쓰는 공유 심볼 이름([06](docs/06-naming-conventions.md) §3), 레포 문서의 확정 사항을 가리키는 결정 색인([07](docs/07-open-questions.md)). 구체 스택·크레이트·버전의 내용은 각 코드 레포 문서가 소유하고, 이 레포는 가리키기만 합니다.

빌드 에이전트는 [`skills/hyperish-spec/SKILL.md`](skills/hyperish-spec/SKILL.md)를 먼저 읽고 작업에 해당하는 문서를 찾아 적용합니다.

## 문서 상태 규칙

모든 문서와 절은 셋 중 하나의 상태를 표시합니다.

| 상태 | 의미 |
|---|---|
| **확정** | 명시적으로 결정된 사실. 바꾸려면 리뷰 승인과 새 결정 기록이 필요하다 |
| **제안** | 논의를 위한 설계안. 바꾸기 쉽게 적은 것이며, 확정이 아니다 |
| **미정** | 아직 결정되지 않은 사항. `docs/07-open-questions.md`에서 추적한다 |

규격(숫자, 한도, 포맷)을 적거나 바꿀 때는 근거(공식 문서 링크 등)와 확인 날짜를 함께 남깁니다.

문서 머리의 상태가 섞여 있으면 절 제목에 상태를 따로 표시합니다. 문서끼리 충돌하면 [00](docs/00-vision.md)의 규약 모델 원칙으로 고르고 [07](docs/07-open-questions.md)에 기록합니다.

## 문서를 바꾸는 법

- 커밋은 문서 단위로 나눕니다. 한 커밋에 관계없는 문서를 섞지 않습니다.
- 커밋 메시지 규약은 [개발 규칙](docs/05-development-rules.md)을 따릅니다. 이 레포의 커밋은 보통 `docs:` 타입입니다.
- **제안** 문서의 내용을 **확정**으로 올리는 변경은 리뷰 승인과 명시적인 결정 기록이 있어야 합니다.
- 특정 제품이나 특정 코드 레포만의 내용을 추가하지 않습니다. 모든 제품이 공유하는 추상 계약인지가 기준입니다(위의 세 가지 예외 제외).
