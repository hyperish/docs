# 08. 저장·공유·권한

> 상태: **제안** · 기준일: 2026-11-16

프로젝트 데이터의 저장, 공유, 권리 모델입니다. 인프라 배치 규칙은 [아키텍처](05-architecture.md), API 형식은 [API 프로토콜 규격](06-api-protocol.md)을 따릅니다.

## 1. 저장 모델

- **자동 저장이 기본**입니다. 수동 저장 버튼은 두지 않습니다. "저장 안 해서 날렸다"는 경험을 원천 차단합니다.
- 모든 저장은 **버전**을 남깁니다. 사용자는 지난 버전으로 되돌릴 수 있습니다.
- 자동 저장과 별개로 **수동 스냅샷**(이름 붙이는 저장)을 둘 수 있습니다.
- 네트워크가 끊기면 편집 내용은 **로컬에 보관**하고, 복구되면 동기화합니다. 전체 오프라인 편집-동기화는 첫 버전 범위가 아닙니다([에디터 UX](02-editor-ux.md) §오프라인). 동기화 중 충돌이 감지되면 조용히 덮어쓰지 않고 사용자에게 선택지를 보여줍니다([실시간 통신 규칙](07-realtime-communication.md) §7).

## 2. 데이터 배치

| 데이터 | 저장소 | 비고 |
|---|---|---|
| 프로젝트, 버전, 사용자, 공유 설정 메타데이터 | D1 | 행 2MB·DB 크기 제한 안에서 |
| 장면 본문(JSON이 큰 경우), 에셋(모델·텍스처·HDRI·렌더 결과물) | R2 | D1에는 색인만 |

## 3. 공유 단계

프로젝트는 **기본 비공개**입니다. 소유자가 명시적으로 단계를 올릴 때만 외부에 열립니다.

```
비공개 → 링크 공유 → 공개 갤러리 등재
```

| 단계 | 누가 볼 수 있나 |
|---|---|
| 비공개 (기본) | 소유자만 |
| 링크 공유 | 링크를 가진 사람. 설치·가입 없이 브라우저에서 열람 |
| 공개 갤러리 | 누구나. 갤러리에 노출 |

"데모가 쏟아지는 모습"을 원하지만, 그것은 만든 사람이 선택할 때 일어나는 일입니다. 시스템이 기본으로 공개하지 않습니다.

공유 철회(링크 삭제, 갤러리 내리기)는 즉시 접근을 차단합니다. 캐시·서빙 처리 규칙은 [API 프로토콜 규격](06-api-protocol.md) §9.

## 4. 리믹스(포크)

- 리믹스는 소유자가 허용한 프로젝트에만 가능합니다.
- 리믹스 결과물에는 **원작 표시를 자동으로 남깁니다**.

## 5. 에셋 권리

에셋 권리는 프로젝트 공유와 **별개**입니다. 남의 모델·텍스처를 가져와 쓴 프로젝트를 공개하면 에셋 라이선스 문제가 생깁니다.

- 업로드 시 "내가 이 에셋을 배포할 권리가 있다"는 확인 절차를 둡니다.
- 에셋마다 라이선스 표기 칸을 둡니다.

## 6. 역할과 권한 (초안)

| 역할 | 보기 | 편집 | 공유 설정 | 삭제 |
|---|---|---|---|---|
| 소유자 | O | O | O | O |
| 편집자 | O | O | X | X |
| 뷰어 | O | X | X | X |

실시간 공동 편집 도입 여부는 [열린 결정](11-open-questions.md)이며, 첫 버전은 소유자 단일 편집을 제안합니다([실시간 통신 규칙](07-realtime-communication.md) §7). 역할 모델은 그 결정과 함께 확정합니다.

## 7. 삭제와 복구

- 프로젝트 삭제는 즉시 영구 삭제가 아니라 **보관(휴지통)으로 이동**하는 것을 제안합니다. 보관 기간은 30일(제안)이며, 그 안에는 복구할 수 있습니다.
- 보관으로 이동하는 순간 해당 프로젝트의 공유 링크와 갤러리 등재는 즉시 비활성화됩니다.
- 보관 기간이 지나 영구 삭제될 때는 D1 메타데이터와 R2 객체(장면 본문, 에셋)를 함께 정리합니다.
