# 02. 코어 공통 계약

> 상태: 코어 참조(ref) 수직화 및 호환 어댑터 분리 원칙은 **확정**, 세부 규칙은 **제안** · 기준일: 2026-11-24

하이퍼리쉬 패밀리의 코드가 공통으로 따르는 추상 계약입니다. 특정 제품의 도메인 모델이나 특정 레포의 구조를 전제하지 않습니다. 구체 스택·라이브러리는 이 문서가 아니라 각 코드 레포의 문서가 확정합니다(결정 색인: [07-open-questions](07-open-questions.md)).

## 1. 내부 모델과 소유권·수명 (코어 ref 수직화)

- **단일 코어 참조(ref)**: 상태성(reactivity/state `signal`), 직렬화(serialization), 파서(parser), 데이터 검증(validation), 범용 스키마 및 규격 인터페이스 등 범용 코어 모델은 `hyve`가 정의·소유하며, 백엔드(`orbic`)와 크로스플랫폼 UI(`serge`, 웹·네이티브) 및 개별 제품 계층은 수직 통합을 위해 이 코어를 공통 기준(ref)으로 삼아 구현합니다.
- 모델은 **한 계층이 소유**합니다. 다른 계층은 읽기 참조로 빌려 쓰고, 변경은 소유 계층에 요청합니다.
- 경계(다른 계층, 다른 프로세스, 외부 어댑터)를 넘을 때는 **명시적 변환**을 거칩니다. 내부 모델의 참조·핸들을 경계 밖으로 그대로 노출하지 않습니다.
- 공유는 불변이 기본입니다. 가변 상태를 공유해야 하면 §4의 규칙을 따릅니다.
- 수명(생성·정리 책임)은 소유 계층이 관리하고, 경계를 넘은 데이터는 수명이 호출 시점으로 제한되거나 명시적 핸들로 관리합니다. 주입 컨텍스트와 반응형 상태는 자신이 만들어진 스코프(앱, 컴포넌트, 요청·작업)에 속하며, 스코프가 끝나면 함께 해제합니다.
- 주입은 조립 시점에 해석합니다. 요청 경로에는 조회 비용만 남기고, 필요한 주입이 빠진 조립은 요청 시점이 아니라 시작 시점에 오류가 됩니다. 한 컴포넌트가 제공한 값은 그 컴포넌트와 그 하위 조립에서만 보이며, 가장 가까운 제공이 우선합니다.

## 2. 오류

| 종류 | 예 | 처리 |
|---|---|---|
| 도메인 오류 | 잘못된 입력, 규칙 위반, 찾을 수 없음 | 구조화된 오류 값으로 반환. 호출자가 분기 가능해야 함 |
| 인프라 오류 | I/O 실패, 외부 서비스 장애, 타임아웃 | 재시도 가능 여부를 표시해 반환. 상위에서 재시도·폴백 판단 |
| 내부 결함 | 버그, 위반된 불변조건 | 오류 값으로 삼키지 않고 빠르게 실패시킴. 실패 범위는 발생한 **격리 경계**(요청, 작업 단위, actor)로 한정하고, 그 위의 복구 정책이 프로세스 전체를 쓰러뜨릴지 결정. 무조건 crash로 고정하지 않음 |

- 계층 안에서는 구조화된 오류 타입으로 전파하고, **외부 어댑터 경계에서는 외부 규약의 오류 형식으로 변환**합니다. 변환 시 내부 구현 세부(스택, 내부 타입명)를 새지 않습니다.
- 오류에는 상관관계 ID를 붙여 로그와 외부 응답을 이을 수 있게 합니다.

## 3. 취소

- 시간이 걸리는 모든 작업은 **취소 가능**해야 하고, 각 작업은 **취소 가능 지점**과 **커밋 지점**(이후에는 취소가 아니라 보상만 가능한 지점)을 명시합니다.
- 취소 신호는 호출 경로를 따라 구조적으로 전파합니다. 작업이 끝난 뒤 도착한 취소는 무시합니다.
- 커밋 지점 전의 취소는 **부분 상태를 남기지 않습니다.** 커밋 지점 후에는 보상을 시도합니다.
- **외부 부수효과가 항상 되돌려지는 것은 아닙니다.** 보상이 불가능한 작업과, 취소 시점에 성공/실패를 알 수 없는 **결과 불명 상태**가 존재합니다. 이런 작업은 멱등 키와 상태 조회로 실제 결과를 확인하는 **재조정 절차**를 함께 둡니다.

## 4. 동시성

- 공유 가변 상태마다 **소유 계층과 불변조건을 문서화**합니다.
- 보호 메커니즘은 **작업 특성과 측정으로 고릅니다**: 조정자 직렬화, 샤딩, 잠금, 원자적 연산, 불변 스냅샷 공유 등을 후보로 두고, 성능·수직 통합 생산성 우선 원칙([00-vision](00-vision.md))에 따라 선택합니다. 단일 조정자 직렬화나 메시지 전달을 전역 기본으로 강제하지 않습니다. 병렬 실행이나 공유 메모리가 유리한 경로에서는 그 구조를 채택하고 불변조건을 해당 구조에 맞게 정의합니다.
- 응용 수준의 동시 변경 정책(같은 대상의 동시 편집 등)은 이 계약이 아니라 각 응용의 결정입니다.

## 5. 어댑터 경계 계약

외부 호환 어댑터([00-vision](00-vision.md)의 규약 모델 원칙)가 지켜야 할 공통 계약입니다. 어댑터는 내부 규약을 외부 규약으로 연결하는 부품입니다.

- **변환**: 내부 모델 ↔ 외부 규약의 매핑을 양방향으로 명세합니다. 변환 코드는 어댑터 안에만 두고, 코어가 외부 규약의 타입을 알지 못하게 합니다.
- **손실**: 외부 규약이 표현 못 하는 내부 값이 나오면 **거부 / 근사 변환 / 보존 필드로 통과** 중 하나를 명시적으로 선택하고 기록합니다. 조용한 소실은 허용하지 않습니다.
- **버전**: 어댑터는 자신이 지원하는 코어 버전 범위와 외부 규약 버전을 선언합니다. 내부 고속 코덱은 양쪽의 스키마·코덱 버전이 일치할 때만 쓰고, 일치하지 않으면 표준 레일로 자동 폴백합니다.
- **단일 파이프라인**: 한 계층에 붙는 모든 진입 어댑터(테스트용 인메모리 클라이언트 포함)는 그 계층이 소유한 하나의 요청 파이프라인을 호출합니다. 권한·검증 단계를 어댑터마다 복제하지 않습니다.
- **비용 및 3단계(3-Tier) 전송 경계**: 변환의 복사·할당 비용을 측정 지점으로 둡니다. 같은 하이퍼리쉬 계층 간에는 거리에 따라 변환 오버헤드를 제거하며, 각 티어의 구체 스택·타입은 해당 코드 레포에서 확정합니다:
  1. **인프로세스(In-Process)**: 직렬화 없이 공유 반응형 상태와 락프리(lock-free) 링 버퍼 등으로 직접 공유합니다.
  2. **로컬 멀티프로세스 IPC**: 로컬 스트림 소켓/파이프 기반 바이너리 RPC와 OS 공유 메모리 기반 링 버퍼(GPU 리소스는 OS 핸들 전달)로 복사 없이 연결합니다. 단, 공유 메모리는 고정 레이아웃(POD) 또는 검증된 바이트 프레이밍, 읽기 찢어짐(tearing) 방지, 크래시 정리, OS 권한 격리(§6) 및 플랫폼 샌드박스 제약을 만족해야 합니다.
  3. **원격 네트워크(Dual-Rail)**: 외부 호환 경계는 표준 어댑터([03](03-api-protocol.md) HTTP/JSON, [04](04-realtime-communication.md) WebSocket)를 쓰고, 하이퍼리쉬 계층 간에는 내부 고속 바이너리 코덱과 저지연 다중 스트림 전송으로 직결합니다. 저지연 전송을 열 수 없으면 표준 실시간 전송을 운반체로 삼아 같은 코덱을 유지합니다([04](04-realtime-communication.md) 머리말).
- **인라인 서버 함수 경계(확정)**: 클라이언트에서 서버 핸들러를 일반 비동기 함수처럼 호출하는 경우에도 숨겨진 전역 자동 등록을 허용하지 않습니다. 서버 빌드에서는 컴포넌트 조립 경계(권한 가드·레이트리밋·접두어 마운트)에 명시 등록하고, 클라이언트 빌드에서는 서버 전용 컨텍스트·본문을 컴파일 타임에 완전히 제거해 경량 호출 스텁만 남깁니다.

## 6. 접근 권한과 철회

- 보호 대상에 대한 접근은 요청 시점마다 소유 계층이 권한을 확인합니다. 한 번 허용했다고 이후 검사를 생략하지 않습니다.
- 접근 허용을 철회하면 이후 요청부터 차단되어야 합니다. 이 보장을 약하게 하는 캐시나 사전 발급 자격(만료 전까지 유효한 서명 등)을 쓰면, 철회 후에도 남는 노출 시간을 문서에 명시하고 가능한 한 짧게 제한합니다.
- 보호 대상을 저장소 등 하위 계층에서 직접 공개하지 않고, 권한 검사를 거치는 경로로만 제공합니다.
- **자격 증명 값(확정, 2026-11-24)**: 세션, 토큰, 일회용 티켓처럼 접근을 증명하는 값은 암호학적 난수로 만든 추측 불가능한 값입니다. 정렬·식별용 ID를 자격 증명으로 쓰지 않습니다.
- **응답 재사용과 권한(확정, 2026-11-24)**: 캐시나 멱등 응답 저장소처럼 이전 응답을 다시 돌려주는 계층은 권한 검사 뒤에 두고, 재사용 키에 인증 주체를 포함합니다. 한 주체의 응답이 다른 주체에게 재사용되어서는 안 됩니다.
- **철회의 범위(확정, 2026-11-24)**: 접근을 철회하면 그 자격에서 파생된 갱신 수단(리프레시 토큰 등)도 함께 폐기합니다.

## 7. 대용량 전송

- 제어 메시지 채널에 대용량 데이터를 싣지 않습니다. 대용량은 별도 전송 경로로 옮기고 제어 채널에는 참조만 보냅니다.
- 전송 완료 통보를 받아도 검증 없이 활성화하지 않습니다. 존재·크기·무결성을 확인한 뒤 활성화합니다.
- 완료되지 않고 남은 전송물은 정리 규칙을 두어 회수합니다.
