# 06. 코어 공통 계약

> 상태: **제안** · 기준일: 2026-11-16

hyper, ring, lace, hera가 공통으로 따르는 계층 간 계약입니다. 각 레이어 문서([02](02-hyper-framework.md) ~ [05](05-hera-native.md))가 이 계약 위에서 세부를 정합니다. 구체 스택·라이브러리 채택은 이 문서에서 확정하지 않습니다([열린 결정](11-open-questions.md)).

## 1. 내부 모델과 소유권·수명

- 도메인 모델(장면, 프로젝트, 세션 등)은 **한 계층이 소유**합니다. 다른 계층은 읽기 참조로 빌려 쓰고, 변경은 소유 계층에 요청합니다.
- 경계(다른 레이어, 다른 프로세스, 외부 어댑터)를 넘을 때는 **명시적 변환**을 거칩니다. 내부 모델의 참조·핸들을 경계 밖으로 그대로 노출하지 않습니다.
- 공유는 불변이 기본입니다. 가변 상태를 공유해야 하면 §4의 동시성 규칙을 따릅니다.
- 수명(생성·정리 책임)은 소유 계층이 관리하고, 경계를 넘은 데이터는 수명이 호출 시점으로 제한되거나 명시적 핸들로 관리합니다.

## 2. 오류

오류를 세 종류로 나눠 다룹니다.

| 종류 | 예 | 처리 |
|---|---|---|
| 도메인 오류 | 잘못된 입력, 규칙 위반, 찾을 수 없음 | 구조화된 오류 값으로 반환. 호출자가 분기 가능해야 함 |
| 인프라 오류 | I/O 실패, 외부 서비스 장애, 타임아웃 | 재시도 가능 여부를 표시해 반환. 상위에서 재시도·폴백 판단 |
| 내부 결함 | 버그, 위반된 불변조건 | 오류 값으로 삼키지 않고 빠르게 실패시킴. 실패 범위는 발생한 **격리 경계**(요청, 작업 단위, actor)로 한정하고, 그 위의 복구 정책(재시작, 폴백)이 프로세스 전체를 쓰러뜨릴지를 결정. 무조건 프로세스 crash로 고정하지 않음 |

- 계층 안에서는 구조화된 오류 타입으로 전파하고, **외부 어댑터 경계에서는 외부 규약의 오류 형식으로 변환**합니다. 변환 시 내부 구현 세부(스택, 내부 타입명)를 새지 않습니다.
- 오류에는 상관관계 ID(requestId 등)를 붙여 로그와 외부 응답을 이을 수 있게 합니다.

## 3. 취소

- 시간이 걸리는 모든 작업(네트워크, 렌더, 빌드, 대량 변환)은 **취소 가능**해야 하고, 각 작업은 **취소 가능 지점**(어느 단계에서 멈출 수 있는지)과 **커밋 지점**(이후에는 취소가 아니라 보상만 가능한 지점)을 명시합니다.
- 취소 신호는 호출 경로를 따라 구조적으로 전파합니다. 작업이 끝난 뒤 도착한 취소는 무시합니다.
- 커밋 지점 전의 취소는 **부분 상태를 남기지 않습니다.** 커밋 지점 후에는 보상(되돌리기)을 시도합니다.
- **외부 부수효과가 항상 되돌려지는 것은 아닙니다.** 보상이 불가능한 작업(이미 발송된 요청, 이미 노출된 결과)과, 취소 시점에 성공/실패를 알 수 없는 **결과 불명 상태**가 존재합니다. 이런 작업은 멱등 키와 상태 조회로 실제 결과를 확인하는 **재조정(reconciliation) 절차**를 함께 둡니다. 멱등성 규약([07-api-protocol](07-api-protocol.md) §6)과 같은 기준을 씁니다.

## 4. 동시성

- 공유 가변 상태마다 **소유 계층과 불변조건을 문서화**합니다. 어떤 변경이 어느 계층에서 일어날 수 있는지가 명확해야 합니다.
- 그 보호 메커니즘은 **작업 특성과 측정으로 고릅니다**: 조정자 직렬화, 샤딩, 잠금, 원자적 연산, 불변 스냅샷 공유 등을 후보로 두고, 성능·수직 통합 생산성 우선 원칙([00-vision](00-vision.md))에 따라 선택합니다. 단일 조정자 직렬화나 메시지 전달을 전역 기본으로 강제하지 않습니다. 병렬 실행이나 공유 메모리 최적화가 유리한 경로(예: 프레임 루프, 대량 데이터 변환)에서는 그 구조를 채택하고 불변조건을 해당 구조에 맞게 정의합니다.
- 도메인 수준의 동시 변경(같은 문서를 두 곳에서 편집 등)은 이 계약이 아니라 제품별 결정입니다([08-realtime-communication](08-realtime-communication.md) §7, [열린 결정](11-open-questions.md)).

## 5. 어댑터 경계 계약

외부 호환 어댑터([00-vision](00-vision.md)의 규약 모델 원칙)가 지켜야 할 공통 계약입니다.

- **변환**: 내부 모델 ↔ 외부 규약의 매핑을 양방향으로 명세합니다. 변환 코드는 어댑터 안에만 두고, 코어가 외부 규약의 타입을 알지 못하게 합니다.
- **손실**: 외부 규약이 표현 못 하는 내부 값이 나오면 **거부 / 근사 변환 / 보존 필드로 통과** 중 하나를 명시적으로 선택하고 기록합니다. 조용한 소실은 허용하지 않습니다.
- **버전**: 어댑터는 자신이 지원하는 코어 버전 범위와 외부 규약 버전을 선언합니다. 외부 규약 자체의 버전닝은 해당 어댑터 문서(예: [07-api-protocol](07-api-protocol.md) §7)를 따릅니다.
- **비용**: 변환의 복사·할당 비용을 측정 지점으로 둡니다. 성능이 중요한 경로(프레임 루프, 대량 전송)에서 경계 변환 비용이 예산을 넘으면, 어댑터를 우회하는 내부 경로를 설계하되 그 우회가 외부 호환을 깨지 않게 문서화합니다.
