# 04. lace: 웹

> 상태: 레포 역할은 **확정**(2026-11-16), 구조·범위는 **제안/미정** · 기준일: 2026-11-16

lace는 하이퍼리쉬의 웹 레포입니다([00-vision](00-vision.md)). 공통 계약은 [06-core-contracts](06-core-contracts.md)를 따릅니다.

## 역할 (확정)

- 웹 계층을 담당합니다.

## 계층 책임과 의존 방향 (제안)

- lace는 **hyper 코어의 웹 타깃**을 담당하는 계층으로 위치시킵니다: 코어 모델·DSL로 만든 응용이 브라우저에서 동작하도록 하는 연결과, 웹 응용이 공통으로 쓰는 부품을 소유합니다.
- 의존 방향: **lace → hyper**. hyper는 lace를 모릅니다([02-hyper-framework](02-hyper-framework.md)의 의존 방향).
- 제품별 화면·UX 기획은 lace의 범위가 아닙니다([00-vision](00-vision.md)의 문서 범위).

## 확장 지점 (제안)

- **웹 바인딩**: hyper 코어를 웹에서 실행하는 연결부. 코어 Rust의 웹 실행 방식(wasm 등)은 미정이며, 결정되면 이 계층이 담당합니다.
- **웹 어댑터**: ring 등 외부 서비스와 통신할 때 어댑터 경계 계약([06-core-contracts](06-core-contracts.md) §5)을 따르는 클라이언트 측 어댑터.

## 빌드·테스트·진단 흐름 (제안)

- 브라우저 환경에서 도는 통합 테스트를 둡니다(코어 연결부가 실제 브라우저에서 깨지는지가 첫 검증 대상).
- DX 원칙([01-dx-principles](01-dx-principles.md))은 lace에도 그대로 적용합니다: 설치와 첫 실행이 짧고, 에러가 곧 문서여야 합니다.

## 미정

- **lace의 정확한 범위**: 프레임워크의 웹 타깃 런타임인지, 웹 응용(사이트·앱 셸) 자체인지, 둘 다인지는 추가 설명이 필요합니다([열린 결정](11-open-questions.md)).
- 이전 검토안(Astro 사이트, React + Vite 에디터 셸, Workers 배포)과의 관계도 미정입니다. lace가 이 스택 위에 놓이는지, 대체하는지 임의로 정하지 않습니다.
- 스타일·토큰 같은 디자인 공통 요소의 위치(이전 DS 검토안의 계승 여부)도 미정입니다.
