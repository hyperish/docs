- 결정: 코드 레포를 4개로 분리 — hyper(개발 프레임워크), ring(백엔드), lace(웹), hera(네이티브)
  - 날짜: 2026-11-16
  - 이유: 패밀리 전 범위를 범용적으로 다루기 위한 구조
  - 영향: docs/00, 09 (레포 구조), 신규 docs/02~05
- 결정: 코어는 대부분 Rust로 작성
  - 날짜: 2026-11-16
  - 이유: 처음부터 다 깎기에는 공수가 많이 듦
  - 영향: docs/00, 02, 09, 10 (Rust 컨벤션)
- 결정: Rust proc macro로 DSL 제작
  - 날짜: 2026-11-16
  - 이유: 처음부터 다 깎기에는 공수가 많이 듦
  - 영향: docs/01, 02

  - 날짜: 2026-11-16
  - 이유: 내부 생산성 극대화, 외부 호환은 어댑터로 분리
  - 영향: docs/00, 02, 07, 08 (외부 규약 문서의 적용 위치 명시). 구체 스택 선택은 위 열린 결정 #11로 추적

## 결정을 기록하는 법

결정이 나면 이 파일의 표에서 "결정됨" 절로 옮기면서 다음을 남깁니다:

```
- 결정: 무엇을 하기로 했는가
- 날짜
- 이유: 한두 문장
- 영향: 바뀌는 문서/코드
```

규모가 큰 결정은 별도 ADR 문서(`decisions/NNNN-제목.md`)로 남기는 것을 제안합니다.
