# 05. hera: 네이티브

> 상태: 레포 역할은 **확정**(2026-11-16), 구조·범위는 **제안/미정** · 기준일: 2026-11-16

hera는 하이퍼리쉬의 네이티브 레포입니다([00-vision](00-vision.md)). 공통 계약은 [06-core-contracts](06-core-contracts.md)를 따릅니다.

## 역할 (확정)

- 네이티브 계층을 담당합니다.

## 계층 책임과 의존 방향 (제안)

- hera는 **hyper 코어의 네이티브 타깃**을 담당하는 계층으로 위치시킵니다: 코어 모델·DSL로 만든 응용이 각 네이티브 플랫폼에서 동작하도록 하는 연결을 소유합니다.
- 의존 방향: **hera → hyper**. hyper는 hera를 모릅니다.
- 소켓·이벤트 루프 등 OS 직접 제어가 필요한 영역은 이 레포와 연관될 가능성이 높습니다([03-ring-backend](03-ring-backend.md)의 네이티브 분리 논의 참조). 단, 이 연결은 미정입니다.
- 제품별 화면·UX 기획은 hera의 범위가 아닙니다([00-vision](00-vision.md)의 문서 범위).

## 확장 지점 (제안)

- **플랫폼 바인딩**: 플랫폼별(데스크톱 OS, 모바일 OS) 연결부를 바인딩 단위로 분리하고, 공통 부분은 플랫폼 중립으로 둡니다.
- **네이티브 어댑터**: 외부 서비스·프로토콜과의 연결은 어댑터 경계 계약([06-core-contracts](06-core-contracts.md) §5)을 따릅니다.

## 빌드·테스트·진단 흐름 (제안)

- 플랫폼별 크로스 빌드 파이프를 구성하고, 바인딩 단위로 플랫폼 실기기/에뮬레이터 테스트를 둡니다. 타깃 플랫폼이 결정된 뒤 구체화합니다.

## 미정

- **타깃 플랫폼 범위**(데스크톱/모바일, OS)는 미정입니다([열린 결정](11-open-questions.md)).
- hyper 코어와의 바인딩 방식(직접 링크, FFI, IPC 등)도 미정입니다.
- hera의 역할이 프레임워크의 네이티브 타깃인지, 네이티브 응용 자체인지는 lace와 같은 질문이며 함께 결정합니다.
