# 04. 디자인 시스템 (DS)

> 상태: **제안** · 기준일: 2026-11-16

## 왜 DS를 먼저 정하는가

앞으로 만들 벡터·셰이더·사진 편집 툴이 각각 다른 얼굴을 하면 하나의 브랜드로 보이지 않습니다. DS는 그 툴들의 공통 얼굴을 미리 정하는 일입니다.

## 구성

### 1. 토큰

- 색, 간격, 글꼴, 아이콘 규칙. **가장 먼저, 가장 작게** 정합니다. 토큰만으로도 툴 사이의 통일감이 생깁니다.
- 토큰은 **하나의 소스 파일(JSON)**에 정의하고, **CSS 커스텀 프로퍼티로 변환**해 사이트(Astro)와 에디터(React)가 같은 값을 쓰게 합니다.
- 토큰 네이밍 규칙은 [네이밍·코딩 컨벤션](10-naming-conventions.md)을 따릅니다.

### 2. 코어 컴포넌트

- 뷰포트, 속성 패널, 슬라이더, 타임라인처럼 **모든 편집툴이 다시 쓸 부품**입니다.
- 그래픽 엔진 에디터를 만들면서 실제로 쓰는 것만 추립니다.
- 컴포넌트는 **React 패키지**로 만들어 에디터와 미래 툴이 공유합니다.

### 3. 두 개의 DS, 하나의 토큰

| | 에디터용 DS | 마케팅 사이트용 DS |
|---|---|---|
| 성격 | 어두운 작업 환경, 조밀한 컨트롤 | 밝고 넓은 화면 |
| 토큰 | 공유 (같은 색·글꼴 소스) | 공유 (같은 색·글꼴 소스) |
| 컴포넌트 | 에디터 전용 세트 | 사이트 전용 세트 |

성격이 달라 컴포넌트는 분리하되, 색·글꼴 토큰은 공유해 같은 브랜드로 보이게 합니다.

## 도입 순서

DS 전체를 먼저 만들지 않습니다. **토큰과 뷰포트·패널 같은 최소 부품만 첫 에디터와 함께** 만듭니다. 쓰이지 않는 컴포넌트를 미리 디자인하는 것이 가장 흔한 낭비입니다.

1. 토큰 JSON 소스 + CSS 변환 파이프.
2. 첫 에디터가 실제로 쓰는 코어 컴포넌트만 React 패키지로.
3. 이후 툴(벡터·셰이더·사진)이 생길 때마다 실사용 부품을 추가.
