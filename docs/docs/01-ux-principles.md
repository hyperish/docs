# 01. UX 원칙

> 상태: **제안** · 기준일: 2026-11-16

모든 하이퍼리쉬 제품이 따르는 사용성 원칙입니다. 새 기능을 설계하거나 트레이드오프를 판단할 때 이 순서대로 저울질합니다.

## 원칙 1. 진입은 쉽게, 천장은 높게

- 기능의 깊이는 언리얼급을 목표로 하되, **처음 연 사람이 30초 안에 무언가를 화면에 띄우는 경험**을 첫 과제로 둡니다.
- 빈 화면으로 시작하지 않습니다. 스타터 장면·템플릿·예제가 첫 진입의 기본값입니다.
- 고급 기능은 숨기지 않되, 초보자의 첫 동선 위에 올라타지 않게 배치합니다.

## 원칙 2. 같은 장면, 다른 모드

- 개발자는 코드로, 디자이너는 슬라이더와 노드로, 연출자는 타임라인으로 **같은 장면**을 다룹니다.
- 모드 전환은 언제든 자유롭고, 전환해도 편집 내용이 깨지지 않아야 합니다. 어느 모드에서 고쳐도 하나의 장면 데이터를 수정하는 것입니다.
- 이 원칙이 데이터 모델 요구사항으로 이어집니다: 장면은 특정 UI의 표현이 아니라 독립된 포맷이어야 하고, 각 UI는 그 포맷의 편집기일 뿐입니다. 장면 포맷 자체는 [열린 결정](11-open-questions.md)입니다.

## 원칙 3. 결과물이 곧 홍보

- "남들이 이걸로 만든 데모가 쏟아지는 모습"이 생태계 목표이므로, 만들기보다 **내보내고 공유하는 흐름이 더 매끄러워야** 합니다.
- 공유는 한 번의 클릭으로 링크가 나오고, 받은 사람은 설치 없이 브라우저에서 봅니다.
- 단, 공유 여부는 언제나 만든 사람이 선택합니다. 비공개가 기본이라는 원칙은 [저장·공유·권한](08-storage-sharing.md)에서 구체화합니다.

## 원칙이 충돌할 때

- 깊이(원칙 1의 천장)와 진입(원칙 1의 쉬움)이 충돌하면, 진입을 해치지 않는 선에서 깊이를 뒤로 뺍니다. 기능을 없애지 말고 기본 동선에서 내립니다.
- 서버 편의와 사용자 경험이 충돌하면 사용자 경험이 우선입니다. 예: 자동 저장은 구현이 복잡해도 채택하는 쪽입니다.
