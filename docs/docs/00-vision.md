# 00. 비전과 제품 방향

> 기준일: 2026-11-16

## 확정: 사용자가 직접 말한 비전

### 하이퍼리쉬와 첫 제품

- 하이퍼리쉬는 크리에이티브 툴 패밀리입니다.
- 첫 제품은 three.js, wgpu, bevy 계열의 **리얼리스틱 그래픽 엔진**입니다.
- 시뮬레이션 성능과 결과물 퀄리티는 C4D급을 목표로 하고, Unreal이 필요 없는 대안을 지향합니다.
- 이 엔진은 **개발자, 디자이너, 필름 디렉터(연출자)** 사용층을 모두 아우르는 것을 지향합니다.

### 확장과 배포

- 이후 벡터 편집, 셰이더 편집, 사진 편집 툴로 확장합니다(Rive·Illustrator·Photoshop이 하는 영역).
- 엔진은 **오픈소스**로 공개하고, **레지스트리에 올려 SDK로 설치**해 쓸 수 있게 합니다.
- 생태계 목표는 직접 작품을 만드는 계획이 아니라, **다른 사람들이 이 엔진으로 만든 데모와 작품이 많이 나오는 상태**입니다.

## 제안: 비전에서 파생된 방향

아래는 비전을 실행하기 위한 해석이며 확정이 아닙니다. 각 문서에서 제안 상태로 다룹니다.

- 툴 패밀리의 얼굴을 통일하기 위한 공통 디자인 시스템 → [04-design-system](04-design-system.md)
- 같은 장면을 역할별로 다른 방식(코드 / GUI / 타임라인)으로 다루는 모드 구조 → [01-ux-principles](01-ux-principles.md), [02-editor-ux](02-editor-ux.md)
- 서버 인프라로 **Cloudflare R2, D1, Workers를 쓰는 방향을 검토 중**이며, 실시간 통신에는 WebSocket이 유력합니다 → [05-architecture](05-architecture.md), [07-realtime-communication](07-realtime-communication.md)

## 미정

- **엔진 코어 언어와 타깃 플랫폼**(웹 우선인지, 네이티브도 가는지)은 결정되지 않았습니다. 되돌리기 가장 비싼 결정이므로 성능 목표와 개발 방향이 더 모아진 뒤에 정합니다.
- 자체 언어/프레임워크 가능성과, 높은 수준의 소켓·이벤트 루프 직접 제어가 필요한 영역에 네이티브 서비스가 필요한지도 열린 결정입니다. API 처리량과 OS 이벤트 루프·소켓 제어는 다른 문제이므로 구분해서 검토합니다. 이 경우에도 계정·메타데이터·에셋 같은 서비스는 Cloudflare 구성을 유지하는 쪽을 우선 검토합니다.
- 전체 목록: [11-open-questions](11-open-questions.md)

## 이 문서의 역할

이 문서는 "왜 만드는가"만 다룹니다. "어떻게 만드는가"의 대부분(스택 세부, API, 통신 규약)은 각 문서에서 **제안** 상태로 다루며, 여기 적힌 확정 사항과 제안이 충돌하면 확정 사항이 우선합니다.
