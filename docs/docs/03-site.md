# 03. 사이트 (랜딩·문서·갤러리)

> 상태: **제안** · 기준일: 2026-11-16

## 사이트와 제품은 따로

랜딩·문서·갤러리 같은 **웹사이트**와, 엔진·에디터라는 **제품**은 배포 주기와 기술 요구가 다릅니다. 사이트는 가볍게 자주 배포하고, 엔진은 독립된 릴리스 주기로 관리합니다. 레포 구성(모노레포 안의 패키지로 둘지, 별도 레포로 둘지)은 [개발 규칙](09-development-rules.md) §1의 제안을 따릅니다. 스택 상세는 [아키텍처](05-architecture.md)를 봅니다.

## 랜딩의 역할

1. 하이퍼리쉬라는 브랜드를 각인시키는 것.
2. 첫 제품인 그래픽 엔진의 실력을 말이 아니라 화면으로 보여주는 것.

## 랜딩 구성

1. **첫 화면 — 랜딩 자체가 데모.** 실제 엔진으로 렌더된 장면을 랜딩에 바로 심습니다. 방문자가 스크롤하거나 드래그하면 장면이 반응합니다. "언리얼이 필요없다"는 주장의 가장 강한 증거는 랜딩이 곧 데모인 것입니다. 준비가 안 됐을 땐 짧은 영상으로 시작해도 됩니다.
2. **이어서 — 진입로.** "브라우저에서 바로 열리는 데모" 링크와 SDK 설치 한 줄. 개발자는 여기서 코드로 넘어갑니다.
3. **마지막 — 작품 갤러리.** 처음엔 직접 만든 데모 몇 개로 채우고, 나중에 커뮤니티 작품으로 바뀝니다.

## 문서 사이트

- 엔진 SDK 문서, 에디터 가이드, API 레퍼런스를 같은 사이트 체계 안에 둡니다.
- 사이트의 디자인 언어는 [디자인 시스템](04-design-system.md)의 마케팅용 DS를 따릅니다.

## 갤러리

- 갤러리 등재는 공유 단계 중 가장 마지막 단계입니다(비공개 → 링크 공유 → 공개 갤러리). 권한 모델은 [저장·공유·권한](08-storage-sharing.md)을 따릅니다.
