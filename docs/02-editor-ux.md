# 02. 에디터 UX

> 상태: **제안** · 기준일: 2026-11-16

첫 제품인 그래픽 엔진 에디터의 화면 구성과 핵심 작업 흐름입니다. UX 원칙은 [01-ux-principles](01-ux-principles.md)을 따릅니다.

## 화면 구성

화면의 중심은 언제나 **실시간 뷰포트**입니다. 조작 결과가 즉시 반영되는 것이 이 엔진의 존재 이유이므로, 편집 UI는 뷰포트를 가리지 않고 주변에 붙습니다.

| 영역 | 내용 | 동작 |
|---|---|---|
| 가운데 | 실시간 뷰포트 | 카메라 이동, 오브젝트 선택, 기즈모 조작 |
| 왼쪽 | 장면 계층 + 에셋 라이브러리 | 드래그앤드롭으로 모델, 텍스처, HDRI 추가 |
| 오른쪽 | 속성 패널 | 선택한 것의 머티리얼·라이팅·물리 값. 값 변경 즉시 뷰포트 반영 |
| 아래 | 타임라인 | 애니메이션·시뮬레이션 재생. 접을 수 있음 |
| 뷰포트 옆 | 코드 패널 (코드 모드) | 라이브 코드 편집. 코드 변경이 같은 장면에 즉시 반영 |

### 모드

- 같은 장면을 **디자인 모드**(패널/슬라이더/기즈모)와 **코드 모드**(라이브 코드 패널)로 다룹니다. 어느 쪽에서 고쳐도 같은 장면 데이터를 수정합니다.
- 타임라인은 연출(필름 디렉터) 사용층의 주 모드입니다.

## 핵심 작업 흐름

1. **새 장면 열기** — 빈 장면 대신 조명이 잡힌 스타터 장면 몇 개 중에서 고릅니다. 첫 화면에서 바로 결과물이 보여야 합니다.
2. **에셋 가져오기** — 파일을 끌어다 놓으면 업로드가 백그라운드에서 진행되고, 진행 중에도 작업을 멈추지 않습니다.
3. **편집** — 속성 패널과 코드 패널 중 원하는 쪽으로 작업합니다.
4. **저장** — 따로 누르지 않아도 자동 저장되고, 지난 버전으로 되돌릴 수 있습니다. 상세는 [저장·공유·권한](08-storage-sharing.md).
5. **공유** — 공유 버튼을 누르면 링크가 만들어집니다. 받은 사람은 설치 없이 브라우저에서 봅니다.

## 실제로 갈리는 결정들

### 저장: 자동 저장 + 버전 히스토리

수동 저장 버튼 없이 자동 저장과 버전 히스토리를 제공합니다. "저장 안 해서 날렸다"는 경험을 원천 차단하는 쪽입니다. 수동 스냅샷(이름 붙이는 저장)은 별도로 둘 수 있습니다.

### 업로드 실패와 복구

- 큰 모델 파일 업로드가 중간에 끊기면 **이어 올리기**를 지원합니다.
- 실패한 에셋만 목록에 표시해 재시도할 수 있게 합니다. 실패가 조용히 지나가는 것은 최악입니다.

### 오프라인

- 네트워크가 끊겨도 편집은 계속되고, 로컬에 쌓아두었다가 복구되면 동기화하는 방향입니다.
- 구현 범위가 크므로 첫 버전 범위는 **"연결 끊김 시 편집 내용 로컬 보관"**까지로 제한합니다.

### 에디터와 SDK의 양방향

에디터에서 만든 장면을 코드로 읽고, 코드로 만든 장면을 에디터에서 여는 것이 수직통합의 핵심입니다.

- **첫 양방향 범위**: 장면 구조와 머티리얼·조명 값까지.
- **단방향으로 시작**: 물리·커스텀 셰이더는 코드에서만 편집하고 에디터는 읽기만 합니다.
