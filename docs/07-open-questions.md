# 07. 열린 결정 (미정 사항)

> 기준일: 2026-11-19

이 명세 전체에 걸린 공통 미정 사항의 목록입니다. 개별 제품이나 개별 코드 레포 내부의 미정 사항은 해당 레포의 `docs/04-open-questions.md`에서 추적합니다.

## 열려 있는 결정

| # | 결정 | 왜 중요한가 | 지금의 방향(제안) |
|---|---|---|---|
| 1 | 내부 규약 모델의 구체 스택·포맷 | 성능·수직 통합 생산성 우선 원칙은 확정이지만 구체 직렬화·전송 와이어 포맷은 미정 | 미정. 외부 호환은 어댑터로 분리하는 원칙만 확정 |
| 2 | 인라인 서버 함수 호출 계약 및 풀스택 심볼 경계 (`hyve` · `orbic` · `serge`) | 명시적 컴포넌트 조립(`.wrap`/`.mount`)과 인라인 서버 함수의 공존 방식, 클라이언트 빌드 시 서버 의존성 제거 경계, `orbic`/`serge` prelude 간 `component()` 심볼 충돌 해소 필요 | 풀스택 30줄 단일 End-to-End 스니펫을 기준으로 공통 계약과 심볼 네이밍(예: `orbic::component` vs `serge::feature` 등) 확정 |
| 3 | 패밀리 공통 Phase 1~3 마일스톤 컷(Vertical Slice 우선순위) | 불변 아키텍처 원칙(`확정`)과 점진적 확장 기능을 분리하지 않으면 구현 착수 기준이 흐려짐 | Phase 1(코어 수직 슬라이스: 모델·상태·HTTP/DB·Web DOM·Desktop 기본) → Phase 2(실전 풀스택·캐시·SSR·데스크톱 시스템 API/Shm IPC) → Phase 3(모바일 OS 특화·HW SDK·WebTransport·MSA 고도화) 제안 |

## 결정됨

- **3개 코어 레포·패키지명 crates.io 비충돌 고유명 확정 (`hyper` → `hyve`, `ring` → `orbic`, `lace` → `serge`)** (2026-11-19)
  - 이유 및 내용: crates.io 선점 충돌(`hyper`, `ring`, `lace`)을 근본 해소하고 레포명 = crates.io 패키지명 = Rust 크레이트명 = CLI명을 1:1 일치시키기 위해 3개 핵심 프레임워크명을 `hyve`(올인원 코어·CLI), `orbic`(백엔드), `serge`(크로스플랫폼 UI)로 확정함 (`docs/00`, `01`, `02`, `05`, `06`, `SKILL.md`)
- **3개 코어 레포(`hyve`, `orbic`, `serge`) 분리 및 Rust 모노레포(`apps/`, `crates/`) 구조 확정** (2026-11-16 ~ 2026-11-19)
  - 영향: `docs/00`, `05` (기존 웹/네이티브 UI 레포를 `serge` 단일 레포로 통합)
- **`docs`는 범용 추상 계약만 다루고, 제품·레포별 세부는 각 코드 레포 문서에 위임** (2026-11-16)
  - 영향: `README.md`, `docs` 전체 (`serge` 고유 `ui!` DSL 세부 결정은 `serge/docs/04-open-questions.md`로 이관)
- **Rust 코어 기반 + `hyve` 코어(`ref`) 수직 통합 + 외부/타깃 호환 어댑터 분리** (2026-11-16 ~ 2026-11-17)
  - 영향: `docs/00`, `02`, `03`, `04`, `05`, `06`
- **내부 포크 + 단계적 `unit optimization` 운영 확정** (2026-11-16 ~ 2026-11-17)
  - 이유 및 내용: 1단계(범용 추상화·미사용 피처 제거 및 `hyve` 코어 직결) 기본 적용 후, 병목 구간에 2단계(Arena/SoA·SIMD 등 심화 개조) 여지 확보 (`docs/05` §7)
- **영역별 표현 방식 고정(조립은 Rust 체이닝, UI 뷰 마크업은 proc macro DSL) 및 컴포넌트 기반 아키텍처 고점 개방 확정** (2026-11-16 ~ 2026-11-18)
  - 이유 및 내용: 개발 생산성을 기준으로 `serge`의 UI 뷰 마크업은 **proc macro DSL**로 고정(정적 템플릿 최적화·핫리로드·트리 가독성)하고, 도메인 컴포넌트·라우트·가드 조립(`orbic`, `serge`)은 **순수 Rust 메서드 체이닝**으로 고정함 (`docs/00`, `01`)
- **3-Tier 전송 경계 및 계층별 필수 기본기 범위 확정** (2026-11-18)
  - 이유 및 내용: 인프로세스·로컬 IPC·원격 Dual-Rail 3단계 전송 경계(`docs/02` §5)와 코어·백엔드·웹·네이티브 필수 기본기 범위를 확정함. 레포별 세부 크레이트와 구현 Phase 컷은 각 코드 레포(`hyve`, `orbic`, `serge`)의 `docs/00-overview.md` 및 `04-open-questions.md`에서 관리함
